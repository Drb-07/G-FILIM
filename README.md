This project follows the locked Phase 2 ring TFIM instance ($N=4, J=g=1, T=2$, initial label `1010`) and the organizers' required simulator settings. The official starter module `qff_sim.py` is included.

## Run

Always open and run `main.ipynb` from the repository root (`project/`).

Use Python 3.11–3.13 in a clean environment (tested and verified on Python 3.12.10):

```bash
python -m venv .venv
# Windows: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
jupyter nbconvert --to notebook --execute main.ipynb --output main.ipynb
# or run main.ipynb directly in Jupyter Notebook / VS Code
```

The notebook `main.ipynb` is fully self-contained and runs top to bottom without external scripts. It sets `RECOMPUTE = True` by default to re-simulate all benchmarks on CPU in approximately 10 seconds. It writes `s3_scan.csv`, `s3_summary.csv`, `bell.csv`, `resources.csv`, and bonus `mitigation.csv` under `results/tables/`, along with extended analysis tables `s3_d_plateau.csv`, `s3_ring_cx_ablation.csv`, `s3_nstar_margin.csv`, and `s3_decay_fit.csv`. In `results/figures/`, it generates `s3_fidelity_crossover.png`, `processor_D_graph.png`, and `s3_gate_split.png`.

The pipeline uses seed 42, 4096 measurement shots, optimization level 1, and the official noise rates. It computes the exact reference from the locked periodic ring TFIM model (N=4, J=g=1, T=2). The density-matrix fidelity excludes readout noise as specified; the sampled staggered magnetization includes the official readout error.

## Current measured results

With the locked settings, the exact staggered magnetization is M_s(T=2)=0.652444. At 1× noise, the measured optima are:
- Processor A: n*=6, F=0.577419 (runner-up n=7, gap 0.0077)
- Processor B: n*=7, F=0.662816 (runner-up n=6, gap 0.0063)
- Processor D: n*=8, F=0.752817 (runner-up n=7, gap 0.0009)

Bell state verification on Processor D:
- Adjacent pair (0,1): $F = 0.9598 \pm 0.0022$ ($\langle XX \rangle = 0.9463$, $\langle YY \rangle = -0.9468$, $\langle ZZ \rangle = 0.9463$)
- Distant pair (0,2): $F = 0.9459 \pm 0.0025$ ($\langle XX \rangle = 0.9238$, $\langle YY \rangle = -0.9141$, $\langle ZZ \rangle = 0.9458$)

Optional studies:
- **Processor D Plateau Scan:** Steps $n \in [5..11]$ reveal a broad plateau from $n=6$ to $n=10$ ($F > 0.73$), peaking at $n^*=8$ ($F=0.7528$) with $n=7$ ($F=0.7519$) and $n=9$ ($F=0.7447$).
- **Ring-4 CX Ablation:** Confirms that a 4-qubit ring with CX basis requires 64 CX gates at $n=8$ ($F=0.6519$, matching Processor B), and native RZZ cuts the two-qubit count in half to 32 gates, raising fidelity to $0.7528$.

Error mitigation & realism:
- Readout matrix inversion improves $M_s$ from $0.5032$ (77.1%) to $0.5135$ (78.7%).
- Linear ZNE achieves $0.6138$ (94.1% of exact $0.6524$). Section 9 notes that simulation ZNE uses simulator noise scaling; physical hardware requires unitary folding / pulse stretching.

At eight steps, the logical/native two-qubit counts are A 64 (109 after routing, 15 SWAPs), B 64 (64 after routing, no SWAPs), and D 32 (32 after routing, no SWAPs). D's RZZ construction uses one native gate per bond; the CX construction on A/B uses two per bond. This supports the observed higher D fidelity while showing why B also benefits from having the ring cycle.

## Processor D design

Processor D is a four-qubit ring with native RZZ. It matches all four ring bonds directly and allows each Ising interaction to be implemented as one native two-qubit gate. Its assumed error rates equal the official model; it claims no calibration advantage. `results/figures/processor_D_graph.png` is generated by the pipeline.
